# FilmDoodle 團隊

這個專案有五個固定角色（定義在 repo 根目錄的 `.claude/agents/`），每次較大的改版都要經過他們討論、確認美感與沒有侵權，才更新上線。

| 角色 | 檔案 | 負責 |
| --- | --- | --- |
| 網頁美感執行 | `.claude/agents/web-aesthetics.md` | 介面與成品畫面的視覺品質、手機／電腦操作手感、塗鴉框構圖 |
| 侵權審查 | `.claude/agents/ip-compliance.md` | 貼圖原創性、商標用語、字型與素材授權、參考圖不得進 repo |
| 貼圖美術 | `.claude/agents/sticker-artist.md` | 原創貼圖（`js/stickers.js`）與風格包（`js/doodles.js`） |
| 專案總監 | `.claude/agents/project-lead.md` | 整體方向、取捨與優先順序、是否新增職位、維護本文件 |
| 品質與發布（QA） | `.claude/agents/qa-release.md` | 回歸測試（手機寬度、WebKit）、效能、無障礙、快取版本、上線檢查清單、給使用者的實機測試步驟（2026-11-27 新增） |

## 流程

1. **實作**：依使用者需求修改。
2. **第一輪審查（各自獨立）**：四個角色同時看截圖與程式，各自回報。
3. **討論**：把四份意見交給專案總監整合、做取捨、決定必做清單（侵權高風險優先於美感偏好）。
4. **修正**：依決定修改；貼圖類由貼圖美術負責。
5. **確認**：所有角色看修正後的截圖簽核（含 QA 的回歸測試），全部同意才上線。
6. 把結論寫進下方「決策紀錄」。

## 使用者目前的需求（2026-11-27）

- 塗鴉框：仿照使用者提供的五張參考圖的**圖案大小、比例、散落範圍**——不要滿版，數量要少一點、主要在邊緣、主角留白；要能**調整圖案數量**。
- 圖案要**更可愛**，模擬參考圖的風格：奶油白貼紙（白色填色＋粉色細描邊）、白臉小貓＋橘色小魚＋小白花、扁平花草、粉彩細線條小貓、螢光手繪貓咪。
- 底片風格：要有**開閃光燈**的感覺，整體更接近底片。
- 侵權規範：只參考「風格」，不可描摹或近似任何既有角色（Sanrio、LINE FRIENDS、IROHAS、LOMOPIE…）；使用者的參考圖不得放進 repo。

## 長期規範（侵權審查訂定）

- 貼圖：白臉小貓（kt_cat）一定要有嘴巴；貓咪系列不放蝴蝶結；不做「黑臉大白眼的貓」；兔子不畫 X 嘴；新貼圖要先過侵權審查才能進風格包。
- 名稱：介面不使用他人商標當名稱（底片型號、相機品牌、instax 等），改用描述性名稱；聲明統一為「色調為一般底片風格的模擬，非任何廠商官方數值。」
- 素材：repo 只放自製圖檔；使用者參考圖與含他人塗鴉的測試照只能留在本機暫存，不能出現在 README 或作品集截圖。
- 螢光貓頭（nc_cathead）：眼睛維持小圓點，不放大、不加瞳孔或亮點、不做實心黑臉版。
- 貓爪抓痕（nc_scratch）：只用弧線，不加爪印或爪尖。

## 決策紀錄

### 2026-11-27｜第二版（塗鴉框仿參考圖、可愛系列、閃光底片）

**第一輪各自審查**
- 網頁美感：圖案被照片邊緣裁掉太多（25–43%，參考約 10%）、大圖太少層次平、手機「換一組」不在首屏、閃光感比拋棄式還弱。
- 侵權審查：為降低與既有作品相似的風險，舊螢光系列的部分圖案（底片框、刺刺球、愛心、星芒）需重新設計、方塊臉移除 → 高優先；App 圖示、底片型號名稱、相紙名稱 → 中優先；新可愛系列（含白臉小貓）→ 低風險。有條件核准。
- 貼圖美術：8 個需重畫（跳躍貓、坐姿貓、奶油十字、大閃光、棉花糖、小魚、鬱金香、扇形葉），各包缺的代表圖案清單。
- 專案總監：三項需求都「部分達成」；建議新增 QA。

**討論後裁決（專案總監）**
1. 侵權高優先：舊螢光系列部分圖案重新設計、移除方塊臉、首頁裝飾改用新系列、加防呆。
2. 侵權中風險：底片改描述性名稱、相紙改名、160NS→160、App 圖示去臉、更新快取版本。
3. 貼圖美術重畫 8 個＋低風險條件。
4. 塗鴉構圖採用網頁美感的數值（邊緣裁切、大中小層次、各包尺寸與數量；貓咪小魚改「上下」）。
5. 閃光底片加強，驗收標準：和「拋棄式」並排一眼看得出差別。
6. 介面：數量改成 − N 個 ＋（4–30）且「換一組」放旁邊；使用者調過的數量換卡片時保留；排列／風格／文字收進「進階」；可點範圍 44px；刪掉重複的「奶油圍繞」「花草上下」。
7. 正式成立「品質與發布（QA）」。

**延後到下一輪**：每個風格包新增 2 個代表圖案（共 10 個，先過侵權審查）；次要 4 個圖案（花束、蝴蝶結、毛線球、小白花）；內部 id 改名。

**第三輪簽核（修正後）**
- 網頁美感：簽核。被邊緣裁掉的圖案 25–43% → 6–15%，主角區零圖案；手機首屏看得到「− N 個 ＋」和「換一組」；閃光底片中心／角落亮度比 4.4，拋棄式 3.3，看得出差別。
- 侵權審查：核准。高、中、低風險條件全部滿足；repo 沒有參考圖或第三方圖檔。
- 貼圖美術：簽核。順手修了三個小問題：奶油漩渦降低出現率、小魚不再用最小尺寸、螢光跳躍貓只用白／黃。
- QA：可以上線。完整流程（手機寬度＋電腦）沒有錯誤；24MP 照片讀取約 0.9 秒、匯出 0.9–1.8 秒、最大約 1500 萬像素；文字對比 ≥ 6.3:1；可點範圍 44px；舊設定與壞資料不會讓頁面壞掉。已依建議修正：存下來的數值限制在滑桿範圍、換一組與頂列按鈕 44px、文字輸入框加標籤。
- 限制：WebKit 引擎不可用，只用 chromium 模擬 iPhone；測試照片只有示意圖，需要使用者用 iPhone 實機確認（步驟見下）。

**給使用者的 iPhone 實機 5 分鐘測試**
1. 用 Safari 打開 FilmDoodle，看首頁的小圖案正不正常。
2. 按「選擇一張照片」，挑一張最近用 iPhone 拍的照片，照片要出現，不會當掉或跳回首頁。
3. 點「塗鴉框」，每張小卡都點點看：塗鴉在照片邊邊，中間的人留白。
4. 按「−」「＋」調圖案多少，再按「換一組」，看塗鴉有沒有跟著變、按鈕好不好按。
5. 打開「進階」按「轉成貼圖」，一根手指拖一個塗鴉、兩根手指放大和轉動，按紅色叉叉刪掉一個。
6. 「相框」選拍立得、「貼圖」加一個、「日期」打開，看日期是不是那張照片拍的那天。
7. 按「儲存」→「分享／存到相簿」，到「照片」App 看照片清不清楚、塗鴉和日期都在。
8. 關掉網頁再打開，看剛剛調的數量有沒有記住。哪裡卡住就截圖回報。

**下一輪待辦**：每個風格包新增 2 個代表圖案（先過侵權審查）；花束、蝴蝶結、毛線球、小白花改版；去臉後的星芒中間加小閃點；轉成貼圖後避免蓋住日期戳記。

### 2026-11-27｜第三版（新增貼圖、日期不被蓋住）

**工作**
- 貼圖美術新增 10 個原創貼圖：
  - 奶油：蝴蝶、雙閃光
  - 貓咪：坐姿小貓、探頭貓
  - 花草：星形花枝、銀杏
  - 粉彩：趴姿條紋貓、小十字群
  - 螢光貓咪：線條貓頭、抓痕
- 改版：花束、蝴蝶結、毛線球、小白花；去臉星芒中間加小閃點。
- 主開發把新貼圖放進各包。探頭貓貼齊底邊、不旋轉。

**審查與修正**
- 侵權審查：核准（全部低風險），新增兩條長期規範（見上方）。
- 網頁美感：
  - 第一次不簽核，因為探頭貓會重複出現、常擋在底部中間 → 改成每張最多 1 隻、只放左右兩側、「天空」排列不放、銀杏不換色。
  - 第二次不簽核，因為探頭貓放不下時那一格會空掉 → 改成換另一側，仍不行就換同層其他大圖。
  - 第三次：簽核。
- QA：
  - 第一次「修完再上線」：先轉貼圖再開日期時，貼圖會蓋住日期（20 次有 12 次）；開關日期會讓約 95% 的塗鴉換位置。
  - 修正：
    - 塗鴉框改成兩步產生——先當作沒有日期排好，再只移走壓到日期角落的塗鴉，所以開關日期只會移動約 15%。
    - 開日期或切換角落時，自動把蓋住日期的貼圖移開。
  - QA 自己的像素檢查：6480 組＋各種操作順序，重疊都是 0。
- QA 判斷 sw.js 不需要改版本號，因為自己的檔案會先抓網路上最新的。

**仍待處理**
- 「粗糙黑邊」相框會蓋到探頭貓的一點點貓爪，美感上可接受，先不處理。
- 沒有 iPhone 實機、沒有 WebKit，需要使用者實機確認。
