# FilmDoodle 團隊

這個專案有五個固定角色（定義在 repo 根目錄的 `.claude/agents/`），每次較大的改版都要經過他們討論、確認美感與沒有侵權，才更新上線。

| 角色 | 檔案 | 負責 |
| --- | --- | --- |
| 網頁美感執行 | `.claude/agents/web-aesthetics.md` | 介面與成品畫面的視覺品質、手機／電腦操作手感、塗鴉框構圖 |
| 侵權審查 | `.claude/agents/ip-compliance.md` | 貼圖原創性、商標用語、字型與素材授權、參考圖不得進 repo |
| 貼圖美術 | `.claude/agents/sticker-artist.md` | 原創貼圖（`js/stickers.js`）與風格包（`js/doodles.js`） |
| 專案總監 | `.claude/agents/project-lead.md` | 整體方向、取捨與優先順序、是否新增職位、維護本文件 |
| 品質與發布（QA） | `.claude/agents/qa-release.md` | 回歸測試（手機寬度、WebKit）、效能、無障礙、快取版本、上線檢查清單、給使用者的實機測試步驟（2026-11-27 新增） |

## 流程

1. **實作**：依使用者需求修改。
2. **第一輪審查（各自獨立）**：四個角色同時看截圖與程式，各自回報。
3. **討論**：把四份意見交給專案總監整合、做取捨、決定必做清單（侵權高風險優先於美感偏好）。
4. **修正**：依決定修改；貼圖類由貼圖美術負責。
5. **確認**：所有角色看修正後的截圖簽核（含 QA 的回歸測試），全部同意才上線。
6. 把結論寫進下方「決策紀錄」。

## 使用者目前的需求（2026-11-27）

- 塗鴉框：仿照使用者提供的五張參考圖的**圖案大小、比例、散落範圍**——不要滿版，數量要少一點、主要在邊緣、主角留白；要能**調整圖案數量**。
- 圖案要**更可愛**，模擬參考圖的風格：奶油白貼紙（白色填色＋粉色細描邊）、白臉小貓＋橘色小魚＋小白花、扁平花草、粉彩細線條小貓、螢光手繪貓咪。
- 底片風格：要有**開閃光燈**的感覺，整體更接近底片。
- 侵權規範：只參考「風格」，不可描摹或近似任何既有角色（Sanrio、LINE FRIENDS、IROHAS、LOMOPIE…）；使用者的參考圖不得放進 repo。

## 長期規範（侵權審查訂定）

- 貼圖：白臉小貓（kt_cat）一定要有嘴巴；貓咪系列不放蝴蝶結；不做「黑臉大白眼的貓」；兔子不畫 X 嘴；新貼圖要先過侵權審查才能進風格包。
- 名稱：介面不使用他人商標當名稱（底片型號、相機品牌、instax 等），改用描述性名稱；聲明統一為「色調為一般底片風格的模擬，非任何廠商官方數值。」
- 素材：repo 只放自製圖檔；使用者參考圖與含他人塗鴉的測試照只能留在本機暫存，不能出現在 README 或作品集截圖。

## 決策紀錄

### 2026-11-27｜第二版（塗鴉框仿參考圖、可愛系列、閃光底片）

**第一輪各自審查**
- 網頁美感：圖案被照片邊緣裁掉太多（25–43%，參考約 10%）、大圖太少層次平、手機「換一組」不在首屏、閃光感比拋棄式還弱。
- 侵權審查：舊螢光系列（有臉底片框、有臉刺刺球、帶放射線的有臉愛心、方塊臉、有臉星芒）**整組**和 IROHAS 太接近，且已上線 → 高風險；App 圖示、底片商標名、instax、160NS → 中風險；新可愛系列（含白臉小貓）→ 低風險。有條件核准。
- 貼圖美術：8 個需重畫（跳躍貓、坐姿貓、奶油十字、大閃光、棉花糖、小魚、鬱金香、扇形葉），各包缺的代表圖案清單。
- 專案總監：三項需求都「部分達成」；建議新增 QA。

**討論後裁決（專案總監）**
1. 侵權高風險最優先：螢光系列去臉、刪方塊臉、首頁裝飾改用新系列、加防呆。
2. 侵權中風險：底片改描述性名稱、相紙改名、160NS→160、App 圖示去臉、更新快取版本。
3. 貼圖美術重畫 8 個＋低風險條件。
4. 塗鴉構圖採用網頁美感的數值（邊緣裁切、大中小層次、各包尺寸與數量；貓咪小魚改「上下」）。
5. 閃光底片加強，驗收標準：和「拋棄式」並排一眼看得出差別。
6. 介面：數量改成 − N 個 ＋（4–30）且「換一組」放旁邊；使用者調過的數量換卡片時保留；排列／風格／文字收進「進階」；可點範圍 44px；刪掉重複的「奶油圍繞」「花草上下」。
7. 正式成立「品質與發布（QA）」。

**延後到下一輪**：每個風格包新增 2 個代表圖案（共 10 個，先過侵權審查）；次要 4 個圖案（花束、蝴蝶結、毛線球、小白花）；內部 id 改名。
